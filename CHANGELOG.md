## [0.5.0] - 2026-10-31

### Upgrading from 0.4

**Python and installation**
- Python 3.15+ (3.14+ on Windows). `pip install py-json-analyzer[dev]` no longer exists; use the
  `dev` dependency group (`uv sync`, or `pip install --group dev` with pip >= 25.1).

**Command line**
- Removed flags: `--struct-case`, `--field-case`, `--json-tag-case` (naming follows the language),
  `--no-json-tags` (tags are always generated), `--no-pydantic-field` (aliases are always generated),
  `--verbose-logging`/`-vl` (use `--log-level DEBUG`).
- `--kw-only` is now the default; use `--no-kw-only` for positional dataclass fields.
- `--plot-format interactive` is gone; `html` (the new default) opens the report in the browser
  unless `--no-browser`. The curses terminal view is replaced by text charts (`terminal`).
- `--generate` without `--output` prints the raw code when piped; messages go to stderr.

**Generated code**
- Type names come from keys (`RootUserProfile` -> `Profile`, `RootProjectsItem` -> `Project`); a root
  array of objects is named after `--root-name`. Python fields are snake_case; Go fields PascalCase.
- Go uses `any` (Go 1.18+). Dataclasses are keyword-only. TypedDicts keep the JSON keys.
- Timestamps: only RFC 3339 formats are detected. Go `time.Time` is used for date-times only;
  Pydantic uses `datetime`/`date`/`time`/`timedelta`; dataclasses and TypedDicts use `str`.

**Configuration files**
- Removed options are ignored with a warning: `struct_case`, `field_case`, `json_tag_case`,
  `indent_size`, `use_tabs`, `line_ending`, `generate_json_tags`, `string_type`, `bool_type`,
  `unknown_type`, `use_optional`, `pydantic_use_field`, `pydantic_use_alias`, `typeddict_total`,
  `datetime_type`. Go `int_type`/`float_type`/`time_type` remain; Python `int_type`/`float_type` are
  gone. Unknown or invalid options now raise `ConfigError`.

**Python API**
- `analyze_json()` returns a `Node` (use `.kind`, `.fields`, `.items`, `.to_dict()`), not a dict.
  `detect_timestamp()` -> `detect_format()`. `FieldType.TIMESTAMP` -> `DATE_TIME`, `LOCAL_DATE_TIME`,
  `DATE`, `TIME`, `DURATION`.
- Generators: use `create_generator(language, config)` instead of `create_go_generator()`,
  `create_web_api_generator()`, `create_strict_generator()`, `create_python_generator()`,
  `create_dataclass_generator()`, `create_pydantic_generator()`, `create_typeddict_generator()` and
  the `get_*_config()` presets.
- Registry: `get_generator` -> `create_generator`, `list_supported_languages` -> `list_languages`,
  `is_language_supported` -> `is_supported`; `register()` takes a `LanguagePlugin`.
- Naming: `NameTracker`/`sanitize_name` -> `plan_names()`; per-language `go_identifier`,
  `python_class_name`, `python_field_name`.
- Prompts: `json_explorer.utils.prompt_input`/`prompt_input_path` -> `json_explorer.ui.ask`/`ask_path`.
- Search: `search_multiple()` and `compile_query` are gone; call `search()` per query.
- All package errors derive from `JsonExplorerError`.

### Changed
- The prompt helpers moved from `json_explorer.utils` to `json_explorer.ui` (`prompt_input` ->
  `ask`, `prompt_input_path` -> `ask_path`); `json_explorer.utils` now only loads JSON.
- **Breaking:** `analyze_json()` returns a typed `Node` (`kind`, `optional`, `fields`, `items`,
  `kinds`, `format`; `to_dict()` for a plain-dict form) instead of a dict with `type`/`children`/
  `child_type` keys and string markers like `"mixed: int, str"`. `convert_analyzer_output()` and
  `generate_from_analysis()` take a `Node`; `FieldType` is a `StrEnum`.
- **Breaking:** `FieldType.TIMESTAMP` is replaced by `DATE_TIME`, `LOCAL_DATE_TIME`, `DATE`, `TIME`
  and `DURATION`. Go: `date-time` -> `time.Time` (or `string` with `time_type`), others `string`.
  Pydantic: `datetime`, `date`, `time`, `timedelta`. Dataclasses and TypedDicts: `str`.
- **Generated code follows its language's standard formatting:** Go output is gofmt-clean (aligned
  struct fields). Python output matches ruff/black formatting (double quotes, wrapped `Field(...)`
  calls), except that other lines longer than 88 characters (very long keys or type names) are not
  wrapped. Both start with a `Code generated by json_explorer. DO NOT EDIT.` header, which Go tools
  and linters recognize.
- **Breaking:** dataclasses are keyword-only by default (`kw_only=True`), so fields keep their JSON
  order. `--kw-only` is replaced by `--no-kw-only` for positional fields.
- Pydantic models carry type notes only in `Field(description=...)`, not also as comments.
- Go output uses `any` for unknown and mixed values (Go 1.18+) instead of `interface{}`.
- Generated imports are exactly the ones used (no unused `field` import in dataclass output;
  `NotRequired` only when a TypedDict has optional keys).
- Generators keep no per-run state on the instance, so one generator can be reused across calls.
- **Generated type names** come from the JSON key instead of the full path:
  `RootProjectsItemTeamTeamlead` is now `TeamLead`; array items use the singular (`projects` ->
  `Project`, `data` -> `DataItem`); a root array of objects is named after `--root-name`.
- Word splitting understands acronyms and accents: `XMLHttpRequest` -> `xml_http_request`,
  `café` -> `cafe`. Python field names may contain Unicode letters; Go names are ASCII.
- Prompt history is stored in the user state directory (`$XDG_STATE_HOME/json_explorer`,
  `~/Library/Application Support/json_explorer`, or `%LOCALAPPDATA%\json_explorer`) instead of
  the current directory.
- `--verbose-logging` is the documented spelling; `--verbose_logging` still works.
- `RegistryError` is exported from `json_explorer.codegen`.
- Logging follows library best practice: importing json_explorer no longer prints INFO logs to stderr.
  The package logger only has a `NullHandler` and propagates to the root logger; the CLI calls
  `configure_logging()`. Logger names are no longer doubled (`json_explorer.cli`, not
  `json_explorer.json_explorer.cli`), and CLI errors are no longer printed twice.
- Requires Python 3.15+ (3.14+ on Windows, where `windows-curses` has no 3.15 wheels yet).
- Project managed with uv (`uv.lock`, `.python-version`); `requirements.txt` removed.
- `__version__` is now read from package metadata (single source: `pyproject.toml`).
- License metadata uses the SPDX expression `MIT` (PEP 639).
- Lint and format with ruff (replaces black, isort and flake8).

### Added
- The package type-checks cleanly with mypy; CI runs mypy on every push.
- Documentation tests (`tests/test_docs.py`): README and API docs examples must parse, their imports,
  CLI flags and function signatures must match the code, and their config examples must load.
- Language plugins: each target language is one `LanguagePlugin` (generator, aliases, interactive
  handler, CLI flags, examples). Third-party languages can be installed through the
  `json_explorer.languages` entry-point group. `register()` now takes a plugin.
- Compile tests for generated code: Python output is executed and its annotations resolved;
  Go output is checked with `go vet` (run in CI on Linux).
- `JsonExplorerError` base class (exported from `json_explorer`): all package errors (`JSONLoaderError`,
  `GeneratorError`, `RegistryError`, `ConfigError`, `TemplateError`, `CLIError`) now derive from it.
- CI workflow: tests on Ubuntu, macOS and Windows; ruff lint job.
- Publish workflow: runs CI first, checks the tag matches the version, verifies and smoke-tests the built
  distributions, and publishes with PyPI Trusted Publishing (no API token).
- `py.typed` marker: type information is now shipped with the package.

### Fixed
- `null` elements inside arrays were ignored (`[1, null]` became `list[int]`, which Pydantic rejects).
  They are now `list[int | None]` / `[]*int64`.
- TypedDicts typed a key that is present but sometimes `null` as `NotRequired[T]`, which rejects the
  data. The analysis now tells missing keys (`optional`, `NotRequired`) from `null` values
  (`nullable`, `T | None`); the tree view shows both.
- Statistics counted booleans as numbers (`numeric_ranges.min` could be `False`).
- Docs: every Python example parses and every documented import and CLI flag exists.
- `--generate` on a JSON document that is just `null` tried to re-read the input (passing a URL as a
  file path) and failed; it now generates a wrapper with one `value: Any` field.
- Timestamp detection treated `"March"`, `"Monday"`, `"1 hour ago"` and `"10.5"` as timestamps (Go
  output then failed to decode real data). Strings now get a type only when every value follows a
  standard RFC 3339 / JSON Schema format, mapped to what each target can decode (see Changed).
- Only the first 20 array elements were analyzed, so keys appearing later were missed and optional
  keys could be marked required. Every element is analyzed now.
- A value that was an integer in some objects and a float in others became a type conflict
  (`interface{}`/`Any`). It is now a float.
- `--tree raw` printed Rich markup (`[bold yellow]...`) literally.
- An unknown or invalid generator option crashed with a raw `TypeError` (or was silently accepted,
  e.g. `int_type: "int8"`). It now fails with a `ConfigError` naming the option and the valid
  options or values.
- `--language-info` failed without a data file and rejected aliases such as `py`.
- Nested arrays lost a dimension: `[[1, 2]]` was generated as `[]int64` / `list[int]`. All levels are
  kept now (`[][]int64`, `list[list[int]]`), and their element types are named after the key.
- Generated code for nested data referenced types that didn't exist (`RootAddress_1`) and renamed
  fields across structs (`Name_1`, `Name_2`). Every type and field is now named once, before
  rendering, so declarations and references always agree.
- Keys starting with a digit became `_123abc`: unexported in Go (silently never (un)marshalled) and
  rejected by Pydantic. They are now `Field123abc` / `field_123abc`.
- JSON keys are escaped in Go struct tags and Pydantic aliases/descriptions. Keys Go's encoding/json
  can't express as a tag name (containing `"`, `,`, `\`, ...) are left out with a comment instead of
  producing an invalid tag.
- Reserved-word handling was case-insensitive (Go `Type_`, `String_`; Python `Id_`). Go exported
  names can't clash with keywords; Python now only renames keywords and names that would break the
  generated module (`class` -> `class_`; builtins like `id` and `type` are kept).
- TypedDict output renamed keys (`userID` -> `user_id`), so it didn't describe the actual dict. Keys
  are kept; keys that aren't identifiers use the functional form `TypedDict("Root", {...})`.
- Generated Python never imported `datetime`, so any JSON with timestamps produced a module that
  failed on import.
- Two objects suggesting the same type name (e.g. `billing.address` and `shipping.address`) no
  longer overwrite each other; the second becomes `Address2`.
- `--plot` failed with "Unknown output format: interactive" unless `--plot-format` was given.
- `--generate` without `--output` wrapped the code in a Rich header and padding, so redirecting
  it to a file produced invalid code. Piped output is now the raw code; status messages, warnings
  and metadata go to stderr. The analysis spinner no longer writes to stdout or to non-terminals.
- Generated dataclasses raised `TypeError` on import when an optional field (with a default) came
  before a required one. Optional fields now follow required ones (unless `kw_only` is set).
- A file containing an empty `{}` or `[]` was reported as "No data loaded".
- Missing file/URL errors are printed to stderr; the dead "file or URL required" check was fixed.
- Go `time` import detection for combined pointer/slice types (e.g. `[]*time.Time`).
- `codegen.create_config(language)` ignored `language`: it now applies the language's defaults
  (snake_case fields for Python) and rejects unsupported languages.

### Removed
- The undocumented `path_analysis` statistics key, which kept one entry per array index.
- **Breaking:** the curses terminal view and the `windows-curses` dependency. `--plot-format terminal`
  prints text charts, which work in any terminal and on every platform.
- **Breaking:** `--plot-format interactive` (it was the same as `html`). `html` is now the default; the
  report is opened in the browser unless `--no-browser` is given (also when `--save-path` is set).
- **Breaking:** `--verbose-logging` / `-vl`; use `--log-level DEBUG`.
- Interactive mode: the code generation submenu's language/info/template screens (the same
  information as `--list-languages` and `--language-info`; templates are offered while configuring),
  and the main menu's "JMESPath help", "Data summary" and "Save last search results" items (the search
  shows examples and offers saving; statistics cover the summary).
- `JsonSearcher.search_multiple()` and the `compile_query` parameter of `JsonSearcher.search()`.
- The `dateparser` dependency (and with it `regex`, `pytz`, `tzlocal`, `python-dateutil`): about 10 MB
  installed and ~230 ms import time. Analysis is roughly 5x faster on the test suite's data.
- `detect_timestamp()` (use `detect_format()`), `map_analyzer_type()`.
- **Breaking:** the Python `datetime_type` option. Timestamps are `datetime` in Pydantic models (which
  parse them) and `str` in dataclasses and TypedDicts (which hold the JSON string as-is).
- The progress spinner shown by `analyze_json()`: a library function no longer draws terminal UI.
- **Breaking:** options that could only produce broken or never-varying output:
  - `generate_json_tags` / `--no-json-tags` (Go structs without tags mis-map keys such as `first_name`)
  - Go `string_type`, `bool_type`, `unknown_type` (unknown values are now always `any`, Go 1.18+),
    and the `int64` choice for `time_type` (timestamps are strings in JSON)
  - Python `int_type`, `float_type`, `string_type`, `bool_type`, `unknown_type`, `use_optional`
  - `pydantic_use_field`, `pydantic_use_alias` / `--no-pydantic-field` (without aliases renamed fields
    can't parse the JSON)
  - `typeddict_total` (its default `total=False` made required keys optional; TypedDicts now keep
    required keys required and mark optional ones `NotRequired`)

  Config files that still set them load with a warning.
- **Breaking:** factory and preset functions that duplicated `create_generator(language, config)`:
  `create_go_generator`, `create_web_api_generator`, `create_strict_generator`,
  `create_python_generator`, `create_dataclass_generator`, `create_pydantic_generator`,
  `create_typeddict_generator`, `get_web_api_config`, `get_strict_config`, `get_modern_config`,
  `get_minimal_config`, `get_dataclass_config`, `get_pydantic_config`, `get_typeddict_config`,
  `get_strict_dataclass_config`, `get_python_generator_config`, `create_minimal_config`,
  `create_verbose_config`, `create_strict_config`, `validate_language_config`.
- **Breaking:** registry duplicates `get_generator` (use `create_generator`),
  `list_supported_languages` (use `list_languages`), `is_language_supported` (use `is_supported`),
  `get_registry` and `unregister`.
- `NameTracker`, `sanitize_name`, `create_go_name_tracker` and `create_python_name_tracker`,
  replaced by `plan_names()` / `NamePlan` and the per-language `go_identifier`,
  `python_class_name` and `python_field_name`. The Go and Python builtin/keyword lists went with
  them (they only produced unnecessary renames).
- **Breaking:** the `struct_case`, `field_case` and `json_tag_case` options and the `--struct-case`,
  `--field-case` and `--json-tag-case` flags. They could only produce broken code (non-PascalCase
  Go fields are unexported and never (un)marshalled; renamed JSON tags no longer match the JSON).
  Naming now follows the target language: Go types and fields are PascalCase; Python classes are
  PascalCase and fields snake_case.
- **Breaking:** the `indent_size`, `use_tabs` and `line_ending` options, which were never applied.
  Config files that still contain any of these six options load with a warning.
- Decorative comments in generated code (`🗂️ Deeply nested structure`, `📊 Large structure`,
  `◉ Generated from array of objects`, …), which Pydantic also copied into JSON Schema
  descriptions. Plain-text notes remain for fields typed `interface{}`/`Any` (mixed or unknown types).
- The duplicated "has no fields" warning and the "TypedDict classes are type hints only" warning
  that was shown on every TypedDict run.
- Unused API: custom Jinja filters, `render_string`, `template_exists`, `list_templates`,
  `create_template_env`, `to_camel_case`, `to_kebab_case`, `to_screaming_snake_case`,
  `convert_case`, `resolve_conflict` and `clean_identifier` exports, `NameTracker.add`,
  `CodeGenerator.get_import_statements`.
- **Breaking:** the `dev` and `all` extras. `pip install py-json-analyzer[dev]` no longer works;
  development tools are now a PEP 735 `dev` dependency group (`uv sync`, or `pip install --group dev`
  with pip >= 25.1).
